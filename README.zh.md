# all-tasks — DSH web GUI 任务看板插件

[English](README.md) | 中文

一个可热插拔的 DeepSeek Harness (DSH) Web GUI 插件，提供 Host 权威任务账本、真实 DSH 会话执行、Host cron 调度和可选的跨平台空闲睡眠保护。插件只通过 `cordis.patch.yml` 与 profile 机制挂载，不修改 DSH 源码。

> **来源**：All Tasks（全部任务）是由 [cjcox17](https://github.com/cjcox17) 维护的独立项目。它最初 fork 自
> [zhu1090093659/dsh-web](https://github.com/zhu1090093659/dsh-web) monorepo 中的 `dsh-task-board` 包
> （`@linxin666/dsh-client-ui-task-board`），以上游 `v0.3.6` tag 为基线，此后已大幅演进。它使用自己的
> `all-tasks` 设置命名空间、`/api/all-tasks` API 前缀与 `$DSH_HOME/all-tasks/` 账本目录，且不再迁移原包数据。
> 许可证与上游一致，为 Apache-2.0（见 [LICENSE](LICENSE)）。

- 浏览器只是异步视图；关闭页面不会停止 Host 调度或执行结算。
- 每次运行创建独立 DSH 会话，并在发送任务 Prompt 前应用钉住的工作区、agent 预设、模型选择与权限。
- 可选电源保护允许显示器熄灭，同时阻止整机因空闲进入系统睡眠。

## 功能

- **任务看板 UI**：新会话按钮下方的侧边栏入口在宽栏显示图标和文字、在折叠 rail 显示图标；看板提供五列布局、搜索、任务详情、归档/恢复、执行历史和执行会话跳转。归档任务除恢复、删除和查看 transcript 外保持只读，恢复前不能手动或定时执行。
- **Host 权威账本**：任务、计划和执行记录存于 `$DSH_HOME/all-tasks/ledger-v2.json`；浏览器动作只有经 Host 确认后才成为 UI 状态。
- **有界执行历史**：每个任务只保留最近 20 条执行记录；新运行开始时截掉最旧的记录，使账本大小与每次写入成本不随任务历史无限增长。
- **真实执行**：手动运行和定时运行共用 Host runner，新建独立会话、重命名、应用 agent 预设、通过 `session.selectModel` 钉住模型选择、应用 `/permission <id>`，再以 queue 模式发送任务 Prompt。
- **钉子失败即关闭**：工作区缺失、预设缺失或损坏、模型选择被拒绝、权限命令被拒绝时，任务 Prompt 不会发送。
- **任务级模型钉**：每个任务都可以从 Host 模型目录中挑选提供商与模型钉住执行会话，并可选择推理强度（minimal/low/medium/high 或提供商自定义值）；留空则回落到部署默认模型。任务钉住端点时，模型下拉会被收窄到这些端点实际可服务的模型（按端点列表取并集）——端点无法服务的已钉模型仍以陈旧行保留可选并带提示，实际生效的选择绝不会在静默中偏离。
- **自动生成任务标题**：创建任务只需填写执行 Prompt——标题留空时，生成会等你离开执行 Prompt 输入框（失焦）后才让 Host 通过一个短命的后台 DSH 会话根据 Prompt 生成标题（与执行相同的启动管线，只跑一个「仅回复标题」的严格回合；选中模型时同样应用该模型钉），生成后自动填入标题字段。只在输入时不会发起请求，半成品的 Prompt 绝不会发给 LLM。手动标题永远优先（已输入的标题不会被覆盖），**重新生成**按钮可再跑一次生成；失败与即时提交都有确定性兜底（取 Prompt 第一个有意义的行，截断到 80 字符），因此创建绝不会被 LLM 阻塞。生成的标题只是建议：账本变更仍走常规的 `create` 动作。该功能默认开启；**设置 → 插件 → 全部任务 → 自动生成任务标题** 开关可关闭后台生成，同时保留 Prompt 首行兜底。
- **端点模型路由器**：命名计算端点（DeepSeek Official、NAS 上的 LM Studio 等）。端点刻意保持精简——只选一个 DSH 提供方路由，并收窄该提供方的模型与默认模型；并发、token 上限、时段等属于提供方自己的设置，不在这里。每个端点还会设置该提供方的模型请求超时（空闲与总时长）。端点在设置卡片中创建与编辑（**设置 → 插件 → 全部任务 → 端点**）：整表编辑器把 `all-tasks` 命名空间实时写回，任务弹窗的「端点」下拉与路由器立即刷新。路由器按任务的端点优先级顺序选择第一个能服务任务模型的端点（任务自身模型钉，否则用端点的 `defaultModel`）启动每次运行。所有端点都被阻塞时，运行进入排队（不创建会话、不产生费用、重启后仍等待），可服务时自动启动，超过可配置的等待上限（默认 24 小时）才失败。峰值/低谷时段按 DeepSeek 官方规则硬编码（2026-08-23 起：高峰为周一至周五 01:00–04:00 与 06:00–10:00 UTC，其余时间及周六、周日均为错峰），刻意不做配置。
- **任务分组**：一组共享执行策略的命名任务集合，在每个看板列内以独立横幅聚合展示（空分组也会显示在「待办」列，创建后立即可见可管理）。分组是**按工作区隔离**的：分组属于创建它的工作区，只接受钉到该工作区的任务作为成员（不带工作区的分组只接受未分配任务），因此同名分组可以在多个工作区里各自独立、设置互不影响。分组有执行模式——顺序（同一时刻只运行一个成员，按组内成员顺序）或并行（最多同时运行可配置的数量，留空为不限）——组内任务的任何启动（手动、定时、路由自动启动）都受此限制。分组可钉住自己的端点优先级列表（成员的自身钉优先，其次分组，最后全局默认）、可用时段窗口与 off-peak-only 开关（即上面的硬编码 DeepSeek 错峰时段），以及可选的分组 cron。分组 cron 启用后，组内成员继承它并忽略各自的定时；成员结算后，按顺序的下一个可运行成员自动启动。被阻塞的手动运行会显示等待原因（**等待组内插槽** / **等待允许时段** / **等待端点**），插槽或时段一空出就自动启动，与端点排队行为一致。运行中的成员持有其分组的容量插槽：执行结算前不能把它移到别的分组（或移出分组），旧分组绝不会在第一个成员仍在运行时启动第二个成员。看板可直接停止：每个运行中的成员卡片带独立**停止**按钮，分组横幅上的**停止分组**会取消全部运行中的成员并把分组标记为已停止（不再启动任何成员，手动执行与 cron 都被拒绝），横幅的**恢复**按钮解除停止。整个分组可拖到待规划/待办列一次移动全部成员，不必逐个拖动。
- **审批门**：每个任务都有一个审批状态。手动创建的任务默认已批准；通过协议 `create` 动作的程序化创建可以传入 `approved: false` 创建为未批准。未批准的任务不能以任何方式运行——手动执行/重新执行、它自己的 cron、分组自动推进都会被拒绝，直到重新批准（分组序列会跳过它，继续下一个已批准成员）。未批准的任务仍然完全可管理：卡片带**未批准**标记，可移动、编辑、分组；头部**仅看未批准**筛选把整个看板收窄到恰好是当天待批准的任务。在卡片（✓）、任务详情或分组成员行上可一键批准；任务详情还提供**取消批准**。排队等待端点时被取消批准的任务会取消该次运行（落入「已失败」列）；未批准任务被暂停的 cron 会滚动到下一次触发点，批准后恢复节奏。
- **暂停与继续**：每个运行中的任务都可以暂停——会话的当前 turn 被取消但会话保留、运行保持打开并标记为**已暂停**，任何东西都不会结算或为它启动——之后可以继续：在**同一个**会话里重新排队任务 prompt，agent 带着完整历史恢复。控件位于运行中的卡片（⏸ / ▶）、任务详情中打开的执行行（**查看会话**旁）以及详情页脚。暂停可放大到整个**任务分组**（**暂停分组**暂停全部运行中的成员并阻止成员启动，直到**继续分组**）和整个**工作区**（总览行上的 ⏸ 暂停钉在该工作区的每个任务并阻止新启动——包括 cron、排队运行与分组自动推进——直到 **▶** 恢复；**全部任务**行暂停整个看板）。已暂停的工作区显示**已暂停**胶囊，其排队任务显示**等待工作区恢复**。暂停是软性挂起：**停止**仍是把运行取消进「已失败」列的硬停止。
- **工作区总览列表**：打开看板首先看到的是类 Monday.com 的看板表格——列头（工作区 / 待办 / 待批准 / 进行中 / 定时 / 已完成 / 已失败 / 合计）下每个工作区一行，带彩色头像与右对齐的等宽数字计数，外加一行**全部任务**汇总所有工作区（含未分配任务）。点击该行进入其工作区的看板；▸ 箭头把该行就地展开为它的分组（彩色分组头，含名称胶囊、模式徽标、成员数与独立的分组折叠开关）与任务行（状态圆点、标题、对齐的状态标签与徽标），点击任务行打开任务详情；⚙ 按钮打开工作区默认设置。看板始终按工作区收窄，头部的**返回**按钮回到总览，原来的工作区下拉已移除。每列先显示该工作区钉住的任务，再显示**未分配**区（没有钉的任务，运行时回退到最近工作区），任何视图都不会丢失任务；主列只显示该工作区的分组，未分配范围的分组在**未分配**区内展示。被任务钉住但从运行列表消失的工作区（已删除或重命名）仍会出现在总览里，避免钉住的任务无处可寻。
- **看板数据看板与工作区控制**：打开看板首先看到汇总条——任务（待办 / 待批准 / 进行中 / 排队）、已完成（含成功率）、失败（含执行次数）、定时与分组、token 用量与预估费用。token 用量在每次执行结算时从会话的 `assistant/message` 用量采集（输入/输出/缓存/推理），因此只有本改动之后启动的运行才带有用量；预估费用按设置的每 100 万 token 单价（设置 → 插件 → 全部任务）乘以这些 token 计算，两者都具备前显示「—」。工作区行默认展开（分组与工作区均可折叠），每行带 ▶ 运行与 ⏹ 停止控制，以及工作区的 ⏸ 暂停（暂停后变为 ▶ 继续）：运行启动其未分组的**待办**任务（不含待规划）与非停止的分组；停止取消其运行中的未分组任务与分组；暂停是上文「暂停与继续」所述的看板级软暂停——挂起钉在该工作区的全部运行中任务并阻止新启动，直到继续。
- **工作区默认设置**：每个工作区可以保存一组执行默认值（agent 预设、模型与推理强度、端点顺序、权限，以及"新任务默认未批准"开关），在**该工作区的看板**里新建任务时自动预填——总览行或看板头部都提供 ⚙ 入口。默认值由 Host 账本持久化（键为工作区 id，记录非空即存）。任务自身的执行目标在运行时优先；任务留空的任何目标都会回退到其工作区的默认值，最后才落到部署默认——因此在默认值设置前创建、或字段留空的任务，运行时也会使用工作区的设置。
- **按端点模型超时**：DSH 在请求 300 秒内未收到新内容（stream-idle watchdog 默认值）时中止它；本地 LLM 重新计算大消息链或生成较慢时，即使后端仍在产出 token 也会触发。每个端点的编辑行携带该提供方路由的空闲超时（自定义/本地 `llm-pi-ai` 路由还有可选的总请求上限）；保存即写入该提供方自己的 DSH 设置，对该提供方的下一个请求立即生效，对话与任务执行都受影响。
- **Host 调度器**：5 段 cron 支持 `*`、`*/n`、范围、逗号列表、周日 `0/7` 和标准的日期/星期 OR 语义，时间基准为 Host 本地时区。
- **确定性恢复**：已有 session id 的 running execution 在重启后继续观察；没有 session id 的启动中断会取消且不会重发。被取消的运行（用户停止，或会话中途消失）结算为 cancelled，任务进入「已失败」列——停止绝不视为成功。
- **实时同步**：变更返回完整 revision snapshot；SSE 只提示 revision、scheduler 与 power 变化，重连和页面恢复可见时重新拉完整 snapshot。
- **可选空闲睡眠保护**：默认关闭；开启后覆盖全部运行中的 DSH 会话、已启用且未归档的任务计划和未知会话状态。
- **会话视图时间戳与 Token 数**：主会话视图显示每条消息与每个工具调用的运行时间。用户消息的开始时间与助手回合的结束/耗时标签（DSH 默认悬停才显示）常驻可见；每个工具行带一个常显的「HH:MM:SS · 耗时」标签，时间取自会话事件时间戳（更早的日期加 `M/D` 或 `Y/M/D` 前缀）；每个回合末尾显示该回合的输入/输出 Token 数（如「输入 1.2K tok · 输出 350 tok」），取自 assistant 的 usage 事件。默认开启；「设置 → 插件 → 全部任务 → 在会话视图显示时间与 Token 数」开关可恢复官方悬停行为。
- **系统提示词注入**：Host 通过 `SystemPrompt.section` 注册 order 200 的 `plugin:all-tasks` 段；任务看板设置可单独关闭声明而不关闭看板。该提示也会提醒 agent 在最终回复前收尾可见的 `todo_write` 计划列表。

## 架构与协议

- `src/index.ts` 通过官方 `@deepseek-ai/dsh-host-apiproxy` 与 `@deepseek-ai/dsh-host-webserver` SDK 挂载 Host 服务。
- `src/host-ledger.ts` 串行动作，并用临时文件加原子 rename 持久化 `{ schemaVersion: 2, revision, tasks, groups, workspaceDefaults, scheduler, recentRequests }`。
- `src/host-service.ts` 负责 cron tick、错过触发跳过、runner 启动、重启对账和电源保护理由。
- `src/client/host-api.ts` 单次导入旧浏览器数据、提交幂等动作，并把 Host snapshot 当作唯一已确认 UI 状态。
- 同源接口为 `GET /api/all-tasks/state`、`GET /api/all-tasks/events`、`POST /api/all-tasks/action` 与 `POST /api/all-tasks/title-suggest`（标题生成 RPC；仅提供建议，不触碰账本）。
- 所有接口都要求浏览器同源标记。直接访问只允许 DSH loopback origin；同机认证反向代理必须使用显式 Host 白名单和服务端注入 token。POST 还必须为 JSON。普通动作上限 64 KiB，导入上限 2 MiB。action 联合中没有命令、可执行路径、shell 文本或任意参数字段。

## 安装

从本仓库安装，然后重启 `dsh web`。git 托管的插件首次安装时，其构建脚本会被
pnpm 的脚本策略拦截——先运行安装，把 pnpm 打印的精确 key 加到
`$DSH_HOME/profiles/web/pnpm-workspace.yaml` 的 `allowBuilds` 下，再重跑：

```sh
dsh plugin --profile web remove @linxin666/dsh-client-ui-task-board   # 仅当仍装着原版时需要
dsh plugin --profile web add github:cjcox17/all-tasks
```

本地开发安装：

```sh
git clone https://github.com/cjcox17/all-tasks.git
cd all-tasks
pnpm install
pnpm build
dsh plugin --profile web add link:$(pwd)
```

## 配置

| 键 | 默认值 | 行为 |
| --- | --- | --- |
| `enabled` | `true` | 启用 Host 服务与浏览器看板。 |
| `announceToAgent` | `false` | 按需开启：开启后向 agent 系统提示加入任务看板说明。 |
| `preventIdleSleep` | `false` | 存在运行中的 DSH 会话、已启用计划或未知会话状态时，持有一个系统空闲睡眠断言。 |
| `autoTitle` | `true` | 新建任务标题留空时，离开执行 Prompt 输入框（失焦）后通过一个短命的后台会话根据 Prompt 生成标题（仅在输入时不会发起请求；Prompt 首行为兜底；关闭后不发起生成，提交时仍用 Prompt 首行兜底）。 |
| `sessionTimestamps` | `true` | 在主会话视图显示每条消息与每个工具调用的运行时间（消息时间常驻可见，每个工具行带开始时间与耗时标签），并在每个回合末尾显示该回合的输入/输出 Token 数。 |
| `trustedProxyHosts` | `[]` | 仅通过已认证 loopback 反向代理路径接受的规范 `host[:port]` authority 白名单。 |
| `proxyTokenEnv` | `DSH_ALL_TASKS_PROXY_TOKEN` | 保存反向代理 token 的环境变量名；token 本身不会写入插件配置。 |
| `endpointMaxWaitHours` | `24` | 排队运行等待可用端点的最长时间，超时后判定失败。 |
| `defaultEndpoints` | `[]` | 未显式钉端点的任务使用的有序端点列表。 |
| `endpoints` | `[]` | 路由器用于路由任务的命名计算端点（见下）。 |

峰值/低谷时段按 DeepSeek 官方规则硬编码（2026-08-23 起：高峰为周一至周五 01:00–04:00 与 06:00–10:00 UTC，其余时间及周六、周日均为错峰），刻意不做配置——这些时段由 DeepSeek 决定，不由用户配置。分组通过「仅限错峰时段」勾选框使用它。

浏览器直接访问仍限制为 DSH loopback origin。若使用同机认证反向代理，应让 DSH Web 绑定 loopback，配置 `trustedProxyHosts`，在 `proxyTokenEnv` 指定的环境变量中放置高熵 token，并让代理在完成认证后替换（不能透传客户端提供的）`X-Dsh-All-Tasks-Proxy-Token`。代理 Host 必须在白名单内，浏览器 `Origin` 必须与其 authority 相同。修改这些 composition 级代理设置后需重启 Host。

### 端点路由配置

端点在 `all-tasks` 设置命名空间下。设置卡片（**设置 → 插件 → 全部任务 → 端点**）是常规编辑器：列出每个端点、支持增删改排序，选择提供方（限定为已知的 `llm` 提供方路由）、从该提供方的模型列表里收窄服务模型、在其中选默认模型，并设置该提供方的请求超时（空闲与总时长）。保存时整张列表一次性写回——任务弹窗的「端点」下拉与路由器都会实时重载，无需重启。同样的值也以 YAML 形式存放在 `all-tasks` 下，可直接编辑（路由器同样实时重载）；超时字段会写穿到提供方路由自己的设置（`llm-pi-ai` / `llm-deepseek`），这是 DSH 唯一认可超时的地方：

```yaml
all-tasks:
  defaultEndpoints: [deepseek-official]
  endpoints:
    - id: deepseek-official
      name: DeepSeek Official
      provider: deepseek-official    # llm 提供方路由 id
      models: []                     # 为空 = 提供商的全部模型
      defaultModel: deepseek-chat
    - id: lm-studio-nas
      name: LM Studio (NAS)
      provider: lm-studio
      models: [qwen/qwen3.8-27b]     # 收窄到该提供方的模型列表
      defaultModel: qwen/qwen3.8-27b
```

任务按优先级钉端点（新建任务弹窗 / 任务详情 → 端点）；路由器使用第一个能服务任务模型的端点——任务自身模型钉在端点可服务时优先，否则用端点的 `defaultModel`。所有候选都被阻塞时任务显示**等待端点**，模型变得可服务时自动启动。并发、token 上限、时段等属于提供方自己的设置，不在端点上；端点上除选择外的唯一可调项是模型请求超时（空闲与总时长）。

macOS 后端启动 `/usr/bin/caffeinate -i -w <host-pid>`，绝不请求 `-d`。Windows 后端从 `SystemRoot` 启动绝对路径的 Windows PowerShell，固定 helper 只请求 `ES_CONTINUOUS | ES_SYSTEM_REQUIRED`；不请求 `ES_DISPLAY_REQUIRED`，不修改电源计划，也不需要管理员权限。Linux 后端只从 `/usr/bin/systemd-inhibit` 或 `/bin/systemd-inhibit` 启动 systemd-logind `idle` block inhibitor，不请求 `sleep`、`handle-lid-switch` 或显示器/屏保 inhibitor；没有 systemd-logind 时显示 `unsupported` 或可见错误，不启动桌面环境专用替代命令。其他平台报告 `unsupported`。

## 任务分组

分组是按工作区隔离的实体，在界面中创建（在该工作区看板的头部 **+ 新建分组**；从「全部任务」总览创建则为未分配范围），持久化在 Host 账本中，并在每个看板列内以横幅聚合展示成员卡片。分组属于创建它的工作区且终生不变，同名分组可在多个工作区各自独立设置。空分组（没有任何成员）也会显示在「待办」列，创建后立即可见、可编辑、可删除：

- **成员关系**：一个任务最多属于一个分组，且只能加入与自身工作区范围一致的分组——钉到某工作区的任务可加入该工作区的分组，未分配任务只能加入未分配范围的分组；任务移到另一个工作区时会自动离开原工作区的分组。在新建任务弹窗或任务详情（分组栏）中选择，或直接把卡片拖到分组横幅/区域内即可加入（追加到组内顺序末尾）。把成员拖到列背景（所有分组之外）即移出分组。加入分组会把成员追加到组内顺序；移出即取消分组。删除分组会取消所有成员的分组（任务保留），且当任一成员存在未结算运行时会拒绝删除。本改动之前写入的旧账本会在加载时迁移：没有范围的分组在其成员同属一个工作区时采纳该工作区，成员跨工作区混杂的分组摊平为未分配范围（外部成员被移出分组）。
- **加入运行中的分组**：加入一个序列已启动（任一当前成员有过执行记录，运行中或已结算）的分组的任务——新建进组、编辑进组或拖入——会被标记为**待手动**（卡片上带小徽标与悬浮提示）。自动推进链会跳过被标记的成员，新任务绝不会自行启动，而是留在原列等待你显式启动：成员自己的**运行**按钮、分组的**启动分组**按钮、以及下一次分组 cron 触发都属于显式启动，会清除标记并启动它。加入全新的、从未运行过的分组则保持原行为（无标记）。被标记的成员无论何时都可手动启动。
- **执行模式**：顺序模式同一时刻只运行一个成员，按组内成员顺序——成员结算后，下一个可运行成员（待规划/待办、未归档、已批准、未被标记）自动启动。并行模式最多同时运行配置的 `maxParallel` 个（留空为不限）。组内任务的任何启动——手动、分组 cron、路由自动启动——都受分组的容量与窗口限制，未批准成员绝不会被启动（序列跳过它，继续下一个已批准成员）。
- **最终步骤**（合并步骤）：分组编辑器可把组内某个成员指定为**最终步骤**——并行构建的汇合步骤。被指定的成员绝不会与其他成员并行启动（它被排除在并行批次、自动推进链和手动运行之外），直到其他所有成员都已结算：每个成员都处于**已完成**或**已失败**列且没有未结算运行（已归档成员不参与序列）。闸门打开后，推进流程会自动启动它——或等成员全部结算后由**启动分组**/手动运行启动。勾选**要求其他成员全部成功**后，任一成员失败都会阻塞合并，直到失败成员重跑成功或被归档；不勾选时，任意结算结果（成功或失败）都会打开闸门。卡片上带**最终步骤**徽标（闸门未开时显示**等待组成员完成**提示），分组横幅显示**最终步骤 · 等待中**胶囊，任务详情也会注明该角色。移除被指定为最终步骤的成员会同时清除该指定。
- **端点**：分组可钉住端点优先级列表（分组编辑器 → 端点）。成员的有效端点列表为：成员自身钉 > 分组列表 > 全局 `defaultEndpoints`。
- **窗口**：分组可把启动限制在 `allowedHours`（Host 本地时间）和/或硬编码的 DeepSeek 错峰时段（**仅限错峰时段**——高峰为周一至周五 01:00–04:00 与 06:00–10:00 UTC；周末全天错峰）。
- **定时**：分组可启用自己的 cron。启用后组内成员继承它——各自的定时被忽略（详情页会显示提示）——cron 触发序列（第一个可运行成员；随后按成员结算继续链条）。
- **停止与恢复**：分组横幅在任一成员运行时显示**停止分组**——取消全部运行中的成员（结算为 cancelled，任务进入「已失败」列）并把分组标记为已停止；已停止的分组不启动任何成员（手动执行、成员 cron、分组 cron 都被拒绝），横幅显示**已停止**标记与**恢复**按钮。运行中的成员卡片旁有独立的**停止**按钮，可只停单个任务而不影响其他成员。
- **暂停与继续**：停止旁边，分组横幅提供**暂停分组**（⏸）——暂停每个打开的成员执行（会话保留、运行保持打开）并把分组标记为已暂停，任何成员都不能以任何方式启动（手动执行、成员 cron、分组 cron、自动推进），直到**继续分组**（▶）在成员各自的会话里重新排队 prompt 并清除标记。暂停期间横幅显示**已暂停**标记。成员也可从卡片单独暂停（运行中的成员 ⏸，已暂停的成员 ▶），与独立的成员**停止**按钮一样互不影响。
- **顺序**：把卡片拖到相邻卡片的上方或下方即可调整顺序——未分组卡片在列内重排，分组成员在组内重排（都持久化到账本）。编辑任务（标题、描述、提示词、执行目标）不会改变其位置。
- **整组移动**：按住分组横幅任意位置拖到「待规划」或「待办」列可一次移动全部成员（任一成员运行中或分组已停止时不允许），不必逐个拖动卡片。拖动时会有跟随指针的浮动幽灵卡片，并显示落点插入线。
- **等待**：被容量阻塞的手动运行显示**等待组内插槽**；被分组窗口阻塞显示**等待允许时段**；被端点阻塞显示**等待端点**。三者都在 Host 侧排队（不产生费用、重启后仍等待），插槽或时段一空出就自动启动，超过 `endpointMaxWaitHours` 才失败。

## 审批

每个任务都有一个审批状态：**已批准**（默认）或**未批准**。只有显式的未批准状态会被持久化（任务记录上的 `approved: false`）；没有该字段的旧任务视为已批准。状态只是一个门——它不会把任务移出看板，移动、编辑、分组、归档在任何状态下都可用。

- **默认**：手动创建（新建任务弹窗）的任务默认已批准。通过协议 `create` 动作的程序化创建可以传入 `approved: false` 创建未批准任务——适合任何需要人工签字后才能运行的来源（例如其他工具为当天队列创建的任务）。
- **绝不运行**：未批准的任务不能以任何方式运行。手动执行/重新执行被 Host 账本拒绝（`task is not approved`）；它自己的 cron 被挂起——触发点滚动到下一个计划时刻而不启动，批准后恢复节奏；分组自动推进与分组 cron 会跳过它并继续下一个已批准成员；已在等待端点的运行若在等待期间被取消批准则取消该次运行（落入「已失败」列，与停止一致）。
- **查看与批准**：未批准的卡片显示**未批准**标记，看板头部的**仅看未批准**开关把整个看板收窄到恰好是待批准的任务——一天需要批准什么一目了然。可在卡片（✓）或分组成员行上单击批准，或在任务详情中批准；详情也提供**取消批准**，可再次加门。

## 工作区视图

打开看板首先看到**工作区总览列表**：列头（工作区 / 待办 / 待批准 / 进行中 / 定时 / 已完成 / 已失败 / 合计）下每个工作区一行（带彩色头像与右对齐的等宽数字计数），外加一行**全部任务**汇总所有工作区（含未分配任务）。▸ 箭头把该行就地展开为它的分组（彩色分组头，含名称胶囊、模式徽标、成员数与独立的分组折叠开关）与任务行（状态圆点、标题、对齐的状态标签与徽标），点击任务行打开任务详情。点击该行进入其工作区的看板——看板始终按工作区收窄（任务的 `workspaceId` 钉——会话运行所在的工作区）；**全部任务**行打开未收窄的总览。看板头部的**返回**按钮回到总览列表，原来的**工作区**下拉已移除。收窄视图下每列先显示该工作区钉住的任务，再显示**未分配**区（没有钉的任务，运行时回退到最近工作区），任何视图都不会丢失任务。分组按工作区隔离：某工作区的看板主列只显示该工作区的分组，未分配范围的分组显示在其**未分配**区内。该筛选同样作用于归档视图，并与文本搜索叠加。它只是视图状态——不涉及任务、账本或协议的变更。被任务钉住但从运行列表消失的工作区（已删除或重命名）仍会出现在总览里，避免钉住的任务无处可寻。

每个工作区行（以及**全部任务**行）还有一个**暂停**控件：⏸ 暂停整个工作区——钉在该工作区的每个任务的打开执行都会被暂停，工作区被标记为已暂停，任何东西都不会再启动（手动执行、任务 cron、排队运行、分组自动推进），直到 ▶ 继续：重新排队已暂停的会话并清除标记。已暂停的行显示**已暂停**胶囊；该工作区看板里的任务显示各自的**已暂停**标记，排队运行显示**等待工作区恢复**。

## 工作区默认设置

每个工作区可以保存一组**执行默认值**，在**该工作区的看板**里新建任务时自动预填（新建任务弹窗的工作区已选中该工作区）：

- **模式**：新建任务的 agent 预设（留空 = 部署默认）。
- **模型 + 推理强度**：钉住新建任务的模型选择（留空 = 部署默认）。
- **端点**：新建任务的端点优先级顺序（留空 = 无钉）。
- **权限**：新建任务应用 `/permission` 预设（留空 = 会话默认）。
- **新任务默认未批准**：勾选后，该工作区新建的任务默认未批准，批准前不能以任何方式运行。

默认值由 Host 账本持久化：`workspaceDefaults` 映射以工作区 id 为键，记录非空即存；通过协议 `set-workspace-defaults` 动作编辑（补丁语义：`null` 清除字段，全部字段清空即删除该工作区的记录）。入口在工作区总览行与看板头部的 ⚙ 按钮。

在**执行时**，工作区默认值作为任务自身目标之下的回退层：任务自己的模式/模型/端点/权限设置优先；留空的字段回退到工作区默认值；两边都留空才使用部署默认。该规则覆盖所有启动路径——手动执行、重新执行、定时任务、排队运行与分组自动推进——并且工作区默认的模式/模型/权限与任务显式钉住一样经过 fail-closed 检查（默认预设损坏或默认模型选择被拒绝会在发送 Prompt 前失败）。`approved` 默认值刻意不参与运行时回退：它只作用于**创建**（新任务默认未批准），绝不影响已有任务自身的审批状态。模式/模型选择器里留空的「工作区默认」选项会带上生效默认值的名称（工作区有默认值时显示它，否则显示部署默认预设名）；任务详情的执行设置里，端点/权限字段留空而工作区提供了默认值时，仍会显示「工作区默认：…」提示。

## 模型请求超时

DSH 在模型请求 300 秒内未收到新内容（stream-idle watchdog 默认值）时中止它。本地 LLM 重新计算大消息链，或计算速度较慢的模型，即使后端仍在生成 token 也可能超过该窗口，导致执行持续失败。端点编辑器（设置 → 插件 → 全部任务 → 端点）的每个端点行携带该提供方路由的超时字段：

- **空闲超时（秒）**：请求在此秒数内未收到任何新内容块即中止；默认 300。
- **总请求超时（秒）**：整个请求的最长时长（仅自定义/本地 `llm-pi-ai` 提供方）；留空使用后端默认。

保存端点列表即写入该提供方自己的 DSH 设置——`streamIdleTimeoutMs`，pi-ai 路由还有 `timeoutMs`，例如 `~/.dsh/settings.yaml` 中的 `llm-pi-ai.providers.lm-studio.streamIdleTimeoutMs`——由 DSH 的提供方 schema 校验，并对该提供方的下一个请求立即生效，对话与任务执行都受影响。超时按提供方生效（同一路由上的全部模型共享该值），因为这是 DSH 的原生粒度；看板只是编辑 Models 页面所编辑的同一份设置，不涉及 Host、账本或协议的变更。

## 数据存储与迁移

- v2 账本位于 `$DSH_HOME/all-tasks/ledger-v2.json`。POSIX 新文件权限为 `0600`；Windows 继承用户目录 ACL。
- 损坏的 v2 文件会移动到防碰撞的 `ledger-v2.json.corrupt-*` 名称，Host 以空账本和可见 scheduler 错误启动，不覆盖损坏字节。
- All Tasks（全部任务）全新开始，不再导入原 `dsh-task-board` 包的浏览器数据。插件自己的旧浏览器键为 `dsh.allTasks.v1`；每个 origin 首次加载页面时，按稳定 source id 和 request id 导入该键下的数据。任务按 id 合并，浏览器端严格较新的顶层字段优先，时间戳相同时保留 Host 字段，执行记录按 execution id 合并。
- 最近 256 个 request id 与动作的 SHA-256 指纹会随账本持久化，因此 Host 重启后的变更重试仍保持幂等，且不会复制完整动作载荷。
- 只有导入成功并经 Host 确认后，`dsh.allTasks.v2.hostImported` 才保存当前 Host 账本 generation；新建或损坏恢复出的新 generation 会再次接收保留的 v1 数据。v1 localStorage 原值保持不变，作为只读回退备份。
- 同一时间只有一个 Host 进程能通过 `$DSH_HOME/all-tasks/ledger-v2.lock` 持有任务看板账本目录；第二个使用同一 DSH home 的 Host 会失败关闭，不并发写账本。

## 安全模型

- 插件仍处在 DSH Web 既有部署与网络边界内，不返回宽松 CORS 头。state、action 与 SSE 共用同一访问栅栏；裸本地命令行请求不会被当作浏览器请求接受。
- 所有变更载荷使用严格、版本化的判别联合；浏览器不能写入 scheduler 独占时间戳或 execution 结果。
- 工作区、预设、模型选择、权限、cron、任务状态和导入记录都会在 Host 再校验。
- 任务 Prompt 是发给 DSH agent 会话的数据。协议不接受 shell 命令、PowerShell 正文、可执行路径或可配置 helper 参数。
- 电源 helper 使用固定可执行路径、固定参数、`shell: false`，失败后按 1、2、5、10、30 秒有界退避。Linux helper 通过 Host stdin 生命周期退出，使 systemd inhibitor 随 Host 异常退出自动释放。

设置 `DSH_POWER_SMOKE=1` 可在 Windows、macOS 或 Linux 上显式启用原生 helper smoke：真实启动固定 helper、等待 ready、在清理路径释放并确认进程退出，不修改系统电源计划。Linux 会先以有界超时探测 systemd-logind；没有可用 system bus 时原生部分跳过，纯逻辑测试仍可运行。

## 手工验证

1. 挂载插件并重启 `dsh web`，打开任务看板，确认 Host 时区和电源状态可见。
2. 新建并编辑任务；刷新或打开第二个同源标签页，确认两者显示同一 Host revision。
3. 执行一个钉住工作区、预设、模型（含推理强度）和权限的任务；确认出现新会话，并由该会话的 `turn/end` 历史结算任务。
4. 打开设置卡片（设置 → 插件 → 全部任务）→ **端点**，添加一个端点（如服务于本地提供方的 `lm-studio`），选择提供方、勾选其某个模型并设默认模型，确认新建任务弹窗的「端点」下拉立即列出它。再把它钉到一个模型钉不匹配的任务上执行：任务显示**等待端点**，不创建会话，端点在编辑后能服务该模型（或补上默认模型）时自动启动；同时确认执行记录里显示实际使用的端点。
5. 创建含两个待办成员的顺序分组，执行第一个成员，确认第一个结算后第二个自动启动。再加第三个成员并在第一个仍运行时执行它：显示**等待组内插槽**，结算后启动。然后在分组运行期间加入第四个成员（新建进组或把现有卡片拖到横幅上）：确认它显示**待手动**徽标，且运行中的成员结算后它不会启动；用成员自己的**运行**按钮（或分组的**启动分组**按钮）执行它，确认标记清除并启动。
6. 打开看板，确认首先显示**工作区总览列表**：列头下每行右对齐计数，外加**全部任务**行。点击某工作区行的 ▸ 箭头，确认其分组与任务行就地展开（每个分组可独立折叠），点击任务行可打开任务详情。把一个任务钉到一个工作区，另一个任务不钉；点击该工作区行进入其看板，确认列中显示钉住的任务外加**未分配**区（含未钉任务），钉到其他工作区的任务消失；点**返回**回到总览，再点**全部任务**行确认未收窄总览恢复。
7. 在工作区总览的行（或看板头部的 ⚙）打开**工作区默认设置**：设置模式、模型、端点与权限并勾选「新任务默认未批准」，保存；在该工作区的看板新建任务，确认弹窗已选中该工作区并预填这些默认值、未批准开关已勾选，创建出的任务带**未批准**标记且无法运行。再在该工作区新建任务并清空其模式/模型/端点/权限字段：确认模式/模型选择器的留空选项显示「工作区默认（名称）」，端点/权限字段旁显示「工作区默认：…」提示，执行该任务时使用的是工作区的预设、模型、端点和权限（执行记录里能看到默认端点）。把默认值全部清空保存，确认该工作区的默认记录被删除（新建任务不再预填，留空字段回退到部署默认）。
7. 在设置卡片（设置 → 插件 → 全部任务）→ **端点**，把服务于本地提供方（如 `lm-studio`）的端点的空闲超时提高到 600 秒并保存；确认 `~/.dsh/settings.yaml` 出现 `llm-pi-ai.providers.lm-studio.streamIdleTimeoutMs`，然后用该模型执行任务，确认生成块之间的长空闲间隙不再失败。把端点改回默认值即恢复 300 秒。
8. 启用一个即将到期的 cron，关闭全部浏览器页面，确认 Host 仍只创建并结算一次 execution。
9. 让 Host 停止并错过一个 cron 触发点，重启后确认该次被跳过，`nextRunAt` 从当前 Host 时间向后滚动。
10. 开启 `preventIdleSleep` 并运行长任务，让显示器自动熄灭；恢复显示后确认会话继续且 execution 已结算。
11. 关闭设置并禁用所有计划，再停止 DSH，确认 helper 退出；macOS 可用 `pmset -g assertions` 辅助确认插件没有 display-sleep assertion。
12. Linux 可用 `systemd-inhibit --list` 确认只存在 `idle`/`block` 条目；显示器仍按桌面设置关闭，手动睡眠和合盖仍由系统策略处理。
13. 打开新建任务弹窗，标题留空并输入执行 Prompt：出现**离开 Prompt 输入框后自动生成**提示，输入过程中不会发起任何请求。点击离开 Prompt 输入框：出现**正在根据 Prompt 生成标题…**提示，一两秒内标题字段自动填入生成的标题（会话列表里可找到名为 **All Tasks · title** 的短命后台会话）。提交并确认任务携带该标题。清空生成的标题并点**重新生成**再得一个新建议；在已生成标题上手动输入并确认不会被覆盖。在设置卡片关闭**自动生成任务标题**，再只凭 Prompt 创建一个任务，确认它得到 Prompt 首行作为标题且没有生成会话。
14. 创建一个并行分组，包含两个待办成员和一个额外成员；打开分组编辑器（⚙），把额外成员选为**最终步骤**并保存。确认最终步骤卡片显示**最终步骤**徽标且在其他成员未完成时没有运行按钮，横幅显示**最终步骤 · 等待中**。启动分组：只有两个并行成员启动，手动运行最终步骤会被拒绝（`final step waits for all group members to settle`）。把其中一个成员移到**已失败**并结算另一个：确认最终步骤自动启动（默认情况下失败成员也会打开闸门）。再编辑分组勾选**要求其他成员全部成功**，把成员移回待办并重跑（其中一个失败），确认最终步骤保持不动，直到该成员成功为止。

## 已知限制

- Host 停止、系统睡眠或长暂停期间错过的触发点会跳过，绝不排队补跑。
- 同一任务已在运行时会跳过到期出现并滚动到下一 cron 匹配点；任务运行不并发、不排队。
- DST 采用 Host 本地墙上时钟语义：春季跳时中不存在的分钟会跳过，秋季回拨中重复的分钟不会执行第二次。
- 电源保护只阻止空闲系统睡眠，明确允许显示器睡眠与锁屏。
- 合盖、手动睡眠、休眠、关机、低电量强制睡眠和企业电源策略不在保证范围内。
- 插件不创建唤醒定时器，也不能唤醒已经睡眠的机器。
- Linux 需要 systemd-logind 及允许当前用户取得 idle block lock 的策略；容器、WSL、无 system bus 或非 systemd 系统可能显示 `unsupported` 或 `error`。桌面环境是否把 logind idle lock 与显示器空闲联动属于其自身策略，插件不请求屏保或显示器 inhibitor。
- 已启用计划会从未来触发点之前持续持锁，因此可能增加电池消耗。
- Host 执行消耗与普通 DSH agent 会话相同的 API 额度。

## 数据遥测

浏览器半区每个 UTC 日向 dsh-market.com 发送一次匿名安装心跳：仅含一个 localStorage 随机 ID 与本包名，无其他数据。服务端只存储该 ID 的加盐哈希，不存 IP，且只暴露聚合计数。完整契约见 [上游 telemetry 契约](https://github.com/zhu1090093659/dsh-web/blob/dev/docs/telemetry.md)。
