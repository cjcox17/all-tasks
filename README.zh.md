- **工作区总览列表**：打开看板首先看到的是类 Monday.com 的看板表格——列头（工作区 / 待办 / 待批准 / 进行中 / 定时 / 已完成 / 已失败 / 合计）下每个工作区一张卡片：每个工作区都是独立带边框圆角的卡片（彩色头像与右对齐的等宽数字计数），卡片之间留有空隙而不是挤在同一个大框里，外加一张**全部任务**卡片汇总所有工作区（含未分配任务）。点击该行进入其工作区的看板；▸ 箭头把该行就地展开为它的分组（彩色分组头，含名称胶囊、模式徽标、成员数与独立的分组折叠开关）与任务行（状态圆点、标题、对齐的状态标签与徽标），点击任务行打开任务详情；⚙ 按钮打开工作区默认设置。看板始终按工作区收窄，头部的**返回**按钮回到总览，原来的工作区下拉已移除。每列先显示该工作区钉住的任务，再显示**未分配**区（没有钉的任务，运行时回退到最近工作区），任何视图都不会丢失任务；主列只显示该工作区的分组，未分配范围的分组在**未分配**区内展示。从运行列表删除的工作区（在侧边栏移除）在工作区基线加载完成后会连同其任务与分组一起从看板消失：总览不再合成已消失工作区的行，其钉住的任务也会从总览计数、看板（各列与归档）和仪表盘中过滤掉。账本中的钉保持不变——任务仍被记录，只是不再显示。
- **看板数据看板与工作区控制**：打开看板首先看到汇总条——任务（待办 / 待批准 / 进行中 / 排队）、已完成（含成功率）、失败（含执行次数）、定时与分组、token 用量与预估费用。token 用量在每次执行结算时从会话的 `assistant/message` 用量采集（输入/输出/缓存/推理），因此只有本改动之后启动的运行才带有用量；预估费用按设置的每 100 万 token 单价（设置 → 插件 → 全部任务）乘以这些 token 计算，两者都具备前显示「—」。**用量保留窗口**（设置 → 插件 → 全部任务 → **保留最近 N 小时的 token 用量**）会把 token 总量与预估费用都收窄到窗口内结算的运行——设为 24 就只看最近一天（0 表示不限）。它只是显示窗口：账本仍保留全部执行记录、不删除任何数据，Tokens/费用卡片的副标题会带「最近 N 小时」前缀，让收窄后的总量一目了然。工作区行默认展开（分组与工作区均可折叠），每行带 ▶ 运行与 ⏹ 停止控制，以及工作区的 ⏸ 暂停（暂停后变为 ▶ 继续）：运行启动其未分组的**待办**任务（不含待规划）与非停止的分组；停止取消其运行中的未分组任务与分组；暂停是上文「暂停与继续」所述的看板级软暂停——挂起钉在该工作区的全部运行中任务并阻止新启动，直到继续。
- **看板用量图表**：汇总卡片下方，落地视图再展示两张图——**费用趋势**与 **Token 趋势**——由同一个**每小时 / 每日 / 每周**下拉驱动：最近 24 个整点、最近 14 个自然日或最近 8 个以周一为起点的自然周。每个上报了用量的执行都按运行开始时间（浏览器本地时区）分桶；Token 图把计费输入（未命中缓存 + 缓存读取 + 缓存写入）、输出与推理堆叠成柱并带颜色图例，费用图把同样的 token 乘以设置的每百万单价——两者与汇总卡片口径一致（有 token 但未设置单价时，费用面板提示先配置单价）。柱状图是零依赖的纯 HTML/CSS 列（不需要图表库），带原生悬浮提示；只有本改动之后启动的运行才带有用量，与 token 汇总卡片一致。打开看板首先看到**工作区总览列表**：列头（工作区 / 待办 / 待批准 / 进行中 / 定时 / 已完成 / 已失败 / 合计）下每个工作区一张卡片——每个工作区都是独立带边框圆角的卡片（彩色头像与右对齐的等宽数字计数），卡片之间留有空隙而不是挤在同一个大框里——外加一张**全部任务**卡片汇总所有工作区（含未分配任务）。▸ 箭头把该行就地展开为它的分组（彩色分组头，含名称胶囊、模式徽标、成员数与独立的分组折叠开关）与任务行（状态圆点、标题、对齐的状态标签与徽标），点击任务行打开任务详情。点击该行进入其工作区的看板——看板始终按工作区收窄（任务的 `workspaceId` 钉——会话运行所在的工作区）；**全部任务**行打开未收窄的总览。看板头部的**返回**按钮回到总览列表，原来的**工作区**下拉已移除。收窄视图下每列先显示该工作区钉住的任务，再显示**未分配**区（没有钉的任务，运行时回退到最近工作区），任何视图都不会丢失任务。分组按工作区隔离：某工作区的看板主列只显示该工作区的分组，未分配范围的分组显示在其**未分配**区内。该筛选同样作用于归档视图，并与文本搜索叠加。它只是视图状态——不涉及任务、账本或协议的变更。从运行列表删除的工作区（在侧边栏移除）在工作区基线加载完成后会连同其任务与分组一起从看板消失：总览不再合成已消失工作区的行，其钉住的任务也会从总览计数、看板（各列与归档）和仪表盘中过滤掉；基线尚未加载（启动/重连）时筛选暂停，避免列表未就绪把看板清空。账本中的钉保持不变——任务仍被记录，只是不再显示。

每个工作区行（以及**全部任务**行）还有一个**暂停**控件：⏸ 暂停整个工作区——钉在该工作区的每个任务的打开执行都会被暂停，工作区被标记为已暂停，任何东西都不会再启动（手动执行、任务 cron、排队运行、分组自动推进），直到 ▶ 继续：重新排队已暂停的会话并清除标记。已暂停的行显示**已暂停**胶囊；该工作区看板里的任务显示各自的**已暂停**标记，排队运行显示**等待工作区恢复**。

## 工作区默认设置

每个工作区可以保存一组**执行默认值**，在**该工作区的看板**里新建任务时自动预填（新建任务弹窗的工作区已选中该工作区）：

- **模式**：新建任务的 agent 预设（留空 = 部署默认）。
- **模型 + 推理强度**：钉住新建任务的模型选择（留空 = 部署默认）。
- **端点**：新建任务的端点优先级顺序（留空 = 无钉）。
- **权限**：新建任务应用 `/permission` 预设（留空 = 会话默认）。
- **新任务默认未批准**：勾选后，该工作区新建的任务默认未批准，批准前不能以任何方式运行。

默认值由 Host 账本持久化：`workspaceDefaults` 映射以工作区 id 为键，记录非空即存；通过协议 `set-workspace-defaults` 动作编辑（补丁语义：`null` 清除字段，全部字段清空即删除该工作区的记录）。入口在工作区总览行与看板头部的 ⚙ 按钮。

在**执行时**，工作区默认值作为任务自身目标之下的回退层：任务自己的模式/模型/端点/权限设置优先；留空的字段回退到工作区默认值；两边都留空才使用部署默认。该规则覆盖所有启动路径——手动执行、重新执行、定时任务、排队运行与分组自动推进——并且工作区默认的模式/模型/权限与任务显式钉住一样经过 fail-closed 检查（默认预设损坏或默认模型选择被拒绝会在发送 Prompt 前失败）。`approved` 默认值刻意不参与运行时回退：它只作用于**创建**（新任务默认未批准），绝不影响已有任务自身的审批状态。模式/模型选择器里留空的「工作区默认」选项会带上生效默认值的名称（工作区有默认值时显示它，否则显示部署默认预设名）；任务详情的执行设置里，端点/权限字段留空而工作区提供了默认值时，仍会显示「工作区默认：…」提示。

## 模型请求超时

DSH 在模型请求 300 秒内未收到新内容（stream-idle watchdog 默认值）时中止它。本地 LLM 重新计算大消息链，或计算速度较慢的模型，即使后端仍在生成 token 也可能超过该窗口，导致执行持续失败。端点编辑器（设置 → 插件 → 全部任务 → 端点）的每个端点行携带该提供方路由的超时字段：

- **空闲超时（秒）**：请求在此秒数内未收到任何新内容块即中止；默认 300。
- **总请求超时（秒）**：整个请求的最长时长（仅自定义/本地 `llm-pi-ai` 提供方）；留空使用后端默认。

保存端点列表即写入该提供方自己的 DSH 设置——`streamIdleTimeoutMs`，pi-ai 路由还有 `timeoutMs`，例如 `~/.dsh/settings.yaml` 中的 `llm-pi-ai.providers.lm-studio.streamIdleTimeoutMs`——由 DSH 的提供方 schema 校验，并对该提供方的下一个请求立即生效，对话与任务执行都受影响。超时按提供方生效（同一路由上的全部模型共享该值），因为这是 DSH 的原生粒度；看板只是编辑 Models 页面所编辑的同一份设置，不涉及 Host、账本或协议的变更。

## 数据存储与迁移

- v2 账本位于 `$DSH_HOME/all-tasks/ledger-v2.json`。POSIX 新文件权限为 `0600`；Windows 继承用户目录 ACL。
- 损坏的 v2 文件会移动到防碰撞的 `ledger-v2.json.corrupt-*` 名称，Host 以空账本和可见 scheduler 错误启动，不覆盖损坏字节。
- All Tasks（全部任务）全新开始，不再导入原 `dsh-task-board` 包的浏览器数据。插件自己的旧浏览器键为 `dsh.allTasks.v1`；每个 origin 首次加载页面时，按稳定 source id 和 request id 导入该键下的数据。任务按 id 合并，浏览器端严格较新的顶层字段优先，时间戳相同时保留 Host 字段，执行记录按 execution id 合并。
- 最近 256 个 request id 与动作的 SHA-256 指纹会随账本持久化，因此 Host 重启后的变更重试仍保持幂等，且不会复制完整动作载荷。
- 只有导入成功并经 Host 确认后，`dsh.allTasks.v2.hostImported` 才保存当前 Host 账本 generation；新建或损坏恢复出的新 generation 会再次接收保留的 v1 数据。v1 localStorage 原值保持不变，作为只读回退备份。
- 同一时间只有一个 Host 进程能通过 `$DSH_HOME/all-tasks/ledger-v2.lock` 持有任务看板账本目录；第二个使用同一 DSH home 的 Host 会失败关闭，不并发写账本。

## 安全模型

- 插件仍处在 DSH Web 既有部署与网络边界内，不返回宽松 CORS 头。state、action 与 SSE 共用同一访问栅栏；裸本地命令行请求不会被当作浏览器请求接受。
- 所有变更载荷使用严格、版本化的判别联合；浏览器不能写入 scheduler 独占时间戳或 execution 结果。
- 工作区、预设、模型选择、权限、cron、任务状态和导入记录都会在 Host 再校验。
- 任务 Prompt 是发给 DSH agent 会话的数据。协议不接受 shell 命令、PowerShell 正文、可执行路径或可配置 helper 参数。
- 电源 helper 使用固定可执行路径、固定参数、`shell: false`，失败后按 1、2、5、10、30 秒有界退避。Linux helper 通过 Host stdin 生命周期退出，使 systemd inhibitor 随 Host 异常退出自动释放。

## 手工验证

1. 挂载插件并重启 `dsh web`，打开任务看板，确认 Host 时区和电源状态可见。
2. 新建并编辑任务；刷新或打开第二个同源标签页，确认两者都显示更新后的任务（内部 ledger revision 不显示在界面中）。
3. 执行一个钉住工作区、预设、模型（含推理强度）和权限的任务；确认出现新会话，并由该会话的 `turn/end` 历史结算任务。
4. 打开设置卡片（设置 → 插件 → 全部任务）→ **端点**，添加一个端点（如服务于本地提供方的 `lm-studio`），选择提供方、勾选其某个模型并设默认模型，确认新建任务弹窗的「端点」下拉立即列出它。再把它钉到一个模型钉不匹配的任务上执行：任务显示**等待端点**，不创建会话，端点在编辑后能服务该模型（或补上默认模型）时自动启动；同时确认执行记录里显示实际使用的端点。
5. 创建含两个待办成员的顺序分组，执行第一个成员，确认第一个结算后第二个自动启动。再加第三个成员并在第一个仍运行时执行它：显示**等待组内插槽**，结算后启动。然后在分组运行期间加入第四个成员（新建进组或把现有卡片拖到横幅上）：确认它显示**待手动**徽标，且运行中的成员结算后它不会启动；用成员自己的**运行**按钮（或分组的**启动分组**按钮）执行它，确认标记清除并启动。
6. 打开看板，确认首先显示**工作区总览列表**：列头下每个工作区一张独立带边框圆角的卡片（右对齐计数），外加**全部任务**卡片，各工作区卡片之间有间距而不是挤在同一个大框里。点击某工作区行的 ▸ 箭头，确认其分组与任务行就地展开（每个分组可独立折叠），点击任务行可打开任务详情。把一个任务钉到一个工作区，另一个任务不钉；点击该工作区行进入其看板，确认列中显示钉住的任务外加**未分配**区（含未钉任务），钉到其他工作区的任务消失；点**返回**回到总览，再点**全部任务**行确认未收窄总览恢复。
7. 在工作区总览的行（或看板头部的 ⚙）打开**工作区默认设置**：设置模式、模型、端点与权限并勾选「新任务默认未批准」，保存；在该工作区的看板新建任务，确认弹窗已选中该工作区并预填这些默认值、未批准开关已勾选，创建出的任务带**未批准**标记且无法运行。再在该工作区新建任务并清空其模式/模型/端点/权限字段：确认模式/模型选择器的留空选项显示「工作区默认（名称）」，端点/权限字段旁显示「工作区默认：…」提示，执行该任务时使用的是工作区的预设、模型、端点和权限（执行记录里能看到默认端点）。把默认值全部清空保存，确认该工作区的默认记录被删除（新建任务不再预填，留空字段回退到部署默认）。
7. 在设置卡片（设置 → 插件 → 全部任务）→ **端点**，把服务于本地提供方（如 `lm-studio`）的端点的空闲超时提高到 600 秒并保存；确认 `~/.dsh/settings.yaml` 出现 `llm-pi-ai.providers.lm-studio.streamIdleTimeoutMs`，然后用该模型执行任务，确认生成块之间的长空闲间隙不再失败。把端点改回默认值即恢复 300 秒。
8. 启用一个即将到期的 cron，关闭全部浏览器页面，确认 Host 仍只创建并结算一次 execution。
9. 让 Host 停止并错过一个 cron 触发点，重启后确认该次被跳过，`nextRunAt` 从当前 Host 时间向后滚动。
10. 开启 `preventIdleSleep` 并运行长任务，让显示器自动熄灭；恢复显示后确认会话继续且 execution 已结算。
11. 关闭设置并禁用所有计划，再停止 DSH，确认 helper 退出；macOS 可用 `pmset -g assertions` 辅助确认插件没有 display-sleep assertion。
12. Linux 可用 `systemd-inhibit --list` 确认只存在 `idle`/`block` 条目；显示器仍按桌面设置关闭，手动睡眠和合盖仍由系统策略处理。
13. 打开新建任务弹窗，标题留空并输入执行 Prompt：出现**离开 Prompt 输入框后自动生成**提示，输入过程中不会发起任何请求。点击离开 Prompt 输入框：出现**正在根据 Prompt 生成标题…**提示，一两秒内标题字段自动填入生成的标题（会话列表里可找到名为 **All Tasks · title** 的短命后台会话）。提交并确认任务携带该标题。清空生成的标题并点**重新生成**再得一个新建议；在已生成标题上手动输入并确认不会被覆盖。在设置卡片关闭**自动生成任务标题**，再只凭 Prompt 创建一个任务，确认它得到 Prompt 首行作为标题且没有生成会话。
14. 创建一个并行分组，包含两个待办成员和一个额外成员；打开分组编辑器（⚙），把额外成员选为**最终步骤**并保存。确认最终步骤卡片显示**最终步骤**徽标且在其他成员未完成时没有运行按钮，横幅显示**最终步骤 · 等待中**。启动分组：只有两个并行成员启动，手动运行最终步骤会被拒绝（`final step waits for all group members to settle`）。把其中一个成员移到**已失败**并结算另一个：确认最终步骤自动启动（默认情况下失败成员也会打开闸门）。再编辑分组勾选**要求其他成员全部成功**，把成员移回待办并重跑（其中一个失败），确认最终步骤保持不动，直到该成员成功为止。
15. 在落地看板上确认**用量趋势**区渲染在汇总卡片与工作区列表之间，含**费用趋势**与 **Token 趋势**两个面板。没有任何已结算运行前，两个面板都显示暂无用量提示。运行几个任务后，切换共享下拉的**每小时 / 每日 / 每周**，确认两个面板随之重新分桶（24 / 14 / 8 列）且窗口提示更新；把鼠标悬停到某一列查看该桶的悬浮提示。未设置输入/输出单价时费用面板显示配置单价提示而 Token 面板照常出图；设置单价后确认费用面板画出柱形，刻度显示预估花费。
16. 在**设置 → 插件 → 全部任务 → 保留最近 N 小时的 token 用量**填入 24 并保存；执行一个任务，确认看板 Tokens 与预估费用卡片只统计该次运行，且两张卡片的副标题带**最近 24 小时**前缀（更早结算的运行从总量中消失，但执行记录仍留在任务历史里）。改回 0 并确认总量恢复为全部时间。

## 已知限制

- Host 停止、系统睡眠或长暂停期间错过的触发点会跳过，绝不排队补跑。
- 同一任务已在运行时会跳过到期出现并滚动到下一 cron 匹配点；任务运行不并发、不排队。
- DST 采用 Host 本地墙上时钟语义：春季跳时中不存在的分钟会跳过，秋季回拨中重复的分钟不会执行第二次。
- 电源保护只阻止空闲系统睡眠，明确允许显示器睡眠与锁屏。
- 合盖、手动睡眠、休眠、关机、低电量强制睡眠和企业电源策略不在保证范围内。
- 插件不创建唤醒定时器，也不能唤醒已经睡眠的机器。
- Linux 需要 systemd-logind 及允许当前用户取得 idle block lock 的策略；容器、WSL、无 system bus 或非 systemd 系统可能显示 `unsupported` 或 `error`。桌面环境是否把 logind idle lock 与显示器空闲联动属于其自身策略，插件不请求屏保或显示器 inhibitor。
- 已启用计划会从未来触发点之前持续持锁，因此可能增加电池消耗。
- Host 执行消耗与普通 DSH agent 会话相同的 API 额度。

## 数据遥测

浏览器半区每个 UTC 日向 dsh-market.com 发送一次匿名安装心跳：仅含一个 localStorage 随机 ID 与本包名，无其他数据。服务端只存储该 ID 的加盐哈希，不存 IP，且只暴露聚合计数。完整契约见 [上游 telemetry 契约](https://github.com/zhu1090093659/dsh-web/blob/dev/docs/telemetry.md)。
